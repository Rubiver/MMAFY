## 사용 시기

사용자가 새 프로젝트의 문서 구조를 만들어달라고 요청할 때 이 스킬을 사용한다.

## 기능

- 프로젝트 루트에 개요 문서(`AGENTS.md` 또는 `CLAUDE.md`) 생성
- `docs/` 디렉터리에 하위 문서들 생성
  - `RULES.md`: AI가 반드시 참고해야 할 규칙
  - `PRD.md`: 프로젝트 요청서 (비개발자용)
  - `DETAIL_SPEC.md`: 상세 구현 명세서 (개발자용)
  - `phases/phase-1.md` ~ `phase-5.md`: 세부 구현 단계 문서
- `codes/.gitignore` 및 `codes/.env.example` 생성
  - **`.gitignore` 와 `.env`, `.env.example` 은 `./codes/` 디렉터리에 위치해야 한다.**
- `.git` 미존재 시 `git init` 및 초기 커밋

## 실행 절차

### 1. 에이전트 확인

먼저 현재 사용 중인 코딩 에이전트를 확인한다:

- `.claude/` 디렉터리 존재 → **Claude Code** → `CLAUDE.md` 생성
- `.agents/` 디렉터리 존재 또는 Pi Coding Agent → **AGENTS.md** 생성
- 둘 다 없거나 불명확 → 사용자에게 에이전트 종류 질문

### 2. 추가 정보 수집

다음 정보를 충분히 확보한 후 문서 작성을 시작한다. 정보가 부족하면 사용자에게 질문한다:

- 프로젝트의 목적과 기능
- 개발 환경 (언어, 프레임워크, 데이터베이스 등)
- 반드시 지켜야 할 규칙이나 제약사항
- 타겟 사용자 및 플랫폼
- 기타 특별 요구사항

### 3. 개요 문서 생성

프로젝트 루트에 `AGENTS.md` (또는 `CLAUDE.md`) 생성:

- 200줄 이하로 작성
- 프로젝트의 전체 개요 기술
- 하위 문서들의 목적과 경로 명시
- `docs/` 디렉터리 구조 설명

### 4. 하위 문서 생성

#### `docs/RULES.md`

> **[중요] `./docs/RULES.md` 는 단순히 링크로 연결시키는 문서가 아니다. 프로젝트 전체에서 매우 중요한 규정이며, 모든 에이전트가 반드시 숙지해야 하는 핵심 문서이다. 이 문서의 생성과 내용을 소홀히 하지 마라.**

다음 규칙을 포함한다:

- 모든 코드는 `codes/` 디렉터리에 작성, 루트에 코드 직접 작성 금지
- 프로젝트 전체에 중국어 한자 금지 (한국어 한자어 중 한글 표기는 허용)
- 한국어 우선, 사용자는 한국인 가정
- 웹 검색 규칙: Playwright MCP 우선, Google 대신 Bing/DuckDuckGo 사용, 키워드는 간결하게
- `codes/.gitignore` 구성, `.env` 커밋 제외, `codes/.env.example` 별도 관리
  - **`.gitignore` 와 `.env`, `.env.example` 은 `./codes/` 디렉터리에 위치해야 한다.**
- 보안상 민감한 내용은 환경변수 처리
- 포트 사용 시 페이즈 종료 시 정리
- 각 페이즈 마지막에 테스트 체크박스 배치
- 페이즈 완료 시 체크 후 git commit
- 프로젝트 루트에 `./resume.md` 생성 (작업 요약 + 다음 작업)
- `./docs/current-phase-log.md`에 각 페이즈 진행 상황 상세 기록
  - 특정 작업이 성공/실패할 때마다 즉시 기록
  - 로그는 "년/월/일/시/분/초" 형식, 서울 기준 시간
  - **`date` 명령을 반드시 실행**하여 현재 시간을 확인해야 함. 모델이 임의로 시간을 추측하거나 판단하면 절대 안 된다.
- 웹 클라이언트 테스트는 Playwright MCP로 스크린샷 촬영 (`./docs/screenshots/` 저장, 풀스크린)
- Playwright MCP 불능 시 즉시 중단 및 보고
- 함수/메서드에 JavaDoc, JSDoc, docstring 등 철저히 작성
- 모호한 경우 임의 판단 금지, 작업 중지 후 질문
- Python: `uv` 확인 → 없으면 개발자에게 요청, `pip/requirements.txt` 사용 금지
  - `uv init --python 3.12`
  - `uv add 프로그램`
  - `uv run 프로그램`
- Python 항상 가상환경 사용
- 프로젝트 성격에 맞는 추가 규칙 작성

#### `docs/PRD.md`

- 개발 지식이 없는 클라이언트 관점에서 작성
- 개발 전문지식이 전혀 없는 사람이 읽어볼 수 있어야 함
- 일상 업무 용어 사용, 기술 용어 최소화

#### `docs/DETAIL_SPEC.md`

- `PRD.md` 기반의 상세 구현 명세서
- 개발자가 `PRD.md`를 받은 후 작성하는 문서라고 가정
- 기술적 구현 세부사항 포함

#### `docs/phases/phase-N.md` (phase-1 ~ phase-5)

- 구현을 위한 각 페이즈별 문서
- 최소 5개 페이즈로 구성
- 각 페이즈 마지막에 완료 체크리스트 배치
- 웹 클라이언트인 경우 Playwright MCP 테스트 포함
- 마지막 페이즈 (phase-N) 순서:
  1. 전체 코드 검토 후 수정
  2. 리팩토링
  3. 다시 전체 코드 검토 후 수정 (잔존 버그 재확인)

### 5. Git 초기화 및 커밋

- `.git`이 없으면 `git init` 실행
- 생성된 모든 파일 커밋 (`.gitignore` 및 `.env.example` 은 `codes/` 디렉터리 기준)
- 커밋 메시지는 한국어로 작성

## 규칙

1. **중국어 한자 절대 금지** — 모든 문서에서 중국어 한자 사용 금지
2. **한국어 우선** — 한자어는 한글로 표기 (예: "목적", "사용")
3. **문서화만 수행** — 실제 코드 개발은 하지 않음
4. **정보 부족 시 질문** — 모호한 경우 임의 판단 금지
5. **200줄 이하** — 개요 문서는 반드시 200줄 이하
6. **Python은 uv만 사용** — pip, requirements.txt 절대 사용 금지
7. **Playwright MCP 필수** — 웹 테스트는 Playwright MCP로만 수행
8. **RULES.md 중요성** — `./docs/RULES.md` 는 단순 연결 문서가 아닌 프로젝트의 핵심 규정. 반드시 숙지하고 충실하게 작성하라.

## 참고

- 이 스킬은 프로젝트 초기화용이며, 실제 구현은 각 `phase-N.md` 문서를 따르는 별도 에이전트 세션에서 수행한다.
- `resume.md`는 컨텍스트 윈도우가 꽉 찼을 때 세션 재시작을 위해 생성한다.
