## 사용 시기

사용자가 프로젝트 초기화 문서 세트(PRd.md, DETAIL_SPEC.md, RULES.md, phase-N.md 등)의 검증을 요청할 때 이 스킬을 사용한다.

## 기능

- 문서 세트의 연결관계(참조 링크) 검증
- 문서 간 일관성 확인
- 누락된 문서 또는 섹션 점검
- project-initializer 스킬의 생성 규칙과 비교하여 문제점 보고

## 실행 절차

### 1. 생성 프롬프트 확인

먼저 사용자에게 물어본다:

> 이 문서 세트를 만들기 위해 작성한 프롬프트가 있나요?

- 프롬프트가 있다면 그 내용을 확인하여, 문서 세트가 원래 목적에 맞게 만들어졌는지 검증한다.
- 프롬프트가 없다면, 프로젝트의 목적을 사용자에게 질문하여 확인한다.

### 2. 루트 설정 파일 확인

프로젝트 루트에 위치한 `AGENTS.md` 또는 `CLAUDE.md`를 확인한다:

- 어떤 에이전트를 사용하는지 파악
- 하위 문서들의 경로와 참조 링크가 올바르게 연결되어 있는지 확인
- 각 문서가 서로를 적절히 참조하고 있는지 확인

### 3. 문서 연결관계 검증

다음 사항들을 점검한다:

- **AGENTS.md/CLAUDE.md**
  - `docs/RULES.md`, `docs/PRD.md`, `docs/DETAIL_SPEC.md` 링크가 있는지 확인한다.
  - `docs/phases/phase-1.md` ~ `phase-5.md` 링크가 있는지 확인한다.
  - 각 문서의 목적과 경로가 명확히 기술되어 있는지 확인한다.

- **docs/RULES.md**
  - 다른 문서에서 참조하고 있는지 확인한다.
  - 프로젝트 전반에 적용되어야 할 규칙들이 포함되어 있는지 확인한다.
  - **`./docs/RULES.md` 는 단순히 링크로 연결시키는 문서가 아니다. 프로젝트 전체에서 매우 중요한 규정 문서이므로, 그 내용과 구조가 충분히 상세하고 명확하게 작성되었는지 반드시 점검한다.**

- **docs/PRD.md**
  - `DETAIL_SPEC.md`에서 PRD 내용을 참조하고 있는지 확인한다.
  - 개발 지식이 없는 클라이언트 관점에서 작성되어 있는지 확인한다.

- **docs/DETAIL_SPEC.md**
  - `PRD.md`의 내용을 기반으로 작성되어 있는지 확인한다.
  - 개발자가 이해할 수 있을 만큼 상세한지 확인한다.
  - `phases/` 문서들에서 DETAIL_SPEC 을 참조하고 있는지 확인한다.

- **docs/phases/phase-N.md**
  - 각 페이즈가 최소 5개 이상인지 확인한다.
  - 각 페이즈 마지막에 완료 체크리스트가 있는지 확인한다.
  - 페이즈들이 순차적으로 연결되어 있는지 확인한다.
  - 마지막 페이즈에 전체 코드 검토, 리팩토링, 재검토 순서가 있는지 확인한다.

### 4. project-initializer 스킬 기준 검증

`project-initializer` 스킬의 생성 규칙과 비교하여 다음 항목들을 점검한다:

| 항목 | 기준 |
| ------ | ------ |
| 개요 문서 줄 수 | 200 줄 이하 |
| 중국어 한자 | 절대 금지 |
| 한국어 우선 | 한자어는 한글로 표기 |
| Python 도구 | `uv`만 사용, `pip`/`requirements.txt` 금지 |
| 웹 테스트 | Playwright MCP 필수 |
| Git 초기화 | `.git` 미존재 시 `git init` 및 초기 커밋 |
| resume.md | 프로젝트 루트에 생성되어 있는지 확인 |
| current-phase-log.md | `./docs/current-phase-log.md`에 각 페이즈 진행 상황 상세 기록 (작업 성공/실패 시 즉시 기록) |
| 시간 형식 | "년/월/일/시/분/초" 형식, 서울 기준 |
| 시간 확인 | **`date` 명령을 반드시 실행**하여 현재 시간을 확인해야 함. 모델이 임의로 시간을 추측하거나 판단하면 안 된다. |
| 스크린샷 저장 | `./docs/screenshots/` 디렉터리에 저장 |
| `.gitignore` 위치 | `codes/.gitignore` 에 위치해야 함 |
| `.env`/`.env.example` 위치 | `codes/.env`, `codes/.env.example` 에 위치해야 함

- **`.gitignore` 와 `.env`, `.env.example` 은 `./codes/` 디렉터리에 위치해야 한다.** |

### 5. 검토 결과 보고

검토 후 발견된 문제점을 다음 형식으로 정리하여 개발자에게 보고한다:

```markdown
## 검증 결과

### 연결관계 문제
- [문제] 문서 A 에서 문서 B 를 참조하고 있지 않음
- [해결] 문서 A 의 [위치] 에 링크 추가 필요

### 일관성 문제
- [문제] PRD.md 의 기능 X 가 DETAIL_SPEC.md 에 반영되지 않음
- [해결] DETAIL_SPEC.md 의 [위치] 에 기능 X 구현 내용 추가 필요

### 규칙 위반
- [문제] 개요 문서가 200 줄 초과 (현재 234 줄)
- [해결] 개요 문서를 압축하여 200 줄 이하로 줄이기

### 누락된 항목
- [문제] phase-3.md 에 완료 체크리스트가 없음
- [해결] phase-3.md 마지막에 완료 체크리스트 추가
```

## 규칙

1. **중국 한자 절대 금지** — 모든 보고서에서 중국어 한자 사용 금지
2. **한국어 우선** — 한자어는 한글로 표기
3. **구체적인 문제점과 해결 방안 제시** — 단순히 문제만 나열하지 않고, 어떻게 수정해야 하는지 명시
4. **문서 순서 검증** — 페이즈 문서들이 논리적인 순서로 배치되어 있는지 확인
5. **프롬프트 기반 검증** — 가능한 한 원래 프롬프트를 기준으로 문서 완성도 판단

## 참고

- 이 스킬은 `project-initializer` 스킬과 함께 사용된다.
- `project-initializer`가 문서 세트를 생성하면, 이 스킬로 그 완성도를 검증한다.
- 검증 결과는 개발자가 문서를 수정할 때 참고할 수 있도록 구체적이고 실행 가능해야 한다.
