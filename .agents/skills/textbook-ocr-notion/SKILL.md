## 사용 시기

- 사용자가 이미지 기반 전자 교재, PDF 강의 자료, 강의 슬라이드, 스캔 문서의 내용을 Notion 필기로 정리해 달라고 요청할 때 사용한다.
- 로그인된 웹 교재 URL, PDF 또는 페이지 이미지가 제공됐고, OCR 결과를 구조화해야 할 때 사용한다.

## 역할 분리

- Codex는 페이지 범위 선정, 브라우저 조작, 결과 검수, Notion 저장을 맡는다.
- 실제 OCR과 독립 내용 검토는 로컬 Pi Coding Agent의 `qwen3.8-27b` 모델을 사용한다.
- Pi에는 읽기·검색·목록·OCR용 파일 확인만 허용한다. 교재 원문, 코드, Notion 내용을 Pi가 수정하게 하지 않는다.

## 사전 조건

1. 교재 사이트에 접근하려면 사용자가 인증된 브라우저 세션을 제공해야 한다. 로그인 비밀번호, 쿠키, 세션 토큰은 읽거나 기록하거나 전달하지 않는다.
2. Notion 앱과 대상 워크스페이스가 연결돼 있어야 한다. 연결되지 않았으면 Notion 앱 연결과 인증을 요청하고 저장 단계에서 멈춘다.
3. 대상 Notion 데이터베이스 또는 상위 페이지가 정해져 있지 않으면, 새 학습 노트를 만들 위치를 사용자에게 한 번만 질문한다.
4. 저작권 보호를 위해 원문 전체를 복제하지 않는다. 필요한 OCR 원문은 검수용으로만 다루고, Notion에는 요약·개념·예시·출처를 중심으로 기록한다.

## 작업 순서

1. 교재 제목, 단원, 페이지 범위와 학습 목적을 확인한다. 페이지 범위가 없으면 한 단원 또는 최대 10페이지 단위로 제안한다.
2. 인증된 브라우저에서 교재를 열고 페이지별 이미지를 전체 해상도로 캡처한다. 화면에 보이는 페이지 번호와 원본 URL을 함께 기록한다.
3. 각 이미지는 실제 Pi로 OCR한다. 기본 명령 형식은 다음과 같다.

   ```bash
   /home/ssafy/.nvm/versions/node/v24.18.0/bin/pi -p \
     --model qwen3.8-27b \
     --tools read,grep,find,ls \
     @<페이지-이미지> \
     "이 교재 이미지를 한국어로 OCR해. 제목, 본문, 코드, 표, 그림 설명을 구분하고 불확실한 글자는 [판독불가]로 표시해. 내용을 새로 만들지 마."
   ```

4. Codex가 OCR 결과를 이미지와 대조한다. 숫자, 코드, 표, 강조 문구, 고유 이름처럼 오류 영향이 큰 항목은 반드시 재확인한다. 판독이 불확실하면 추정하지 않고 해당 문장을 이미지로 남긴다.
5. Pi에게 검수된 OCR을 바탕으로 핵심 개념, 학습 목표, 예시, 주의점, 확인 문제를 간결하게 정리하게 한다. 원문을 장문으로 복사하지 않는다.
6. Notion에서 기존 교재·단원 노트를 검색한다. 같은 단원이 있으면 업데이트하고, 없으면 지정된 위치에 새 페이지를 만든다.
7. 다음 형식으로 Notion 노트를 저장한다.

   ```markdown
   # <교재명> — <단원명>

   ## 핵심 요약
   ## 핵심 개념
   ## 예시와 코드
   ## 주의점과 헷갈리기 쉬운 부분
   ## 확인 문제
   ## 출처
   - 교재 URL: <URL>
   - 페이지: <범위>
   - 작성일: <서울 시간>
   - OCR 제한: <판독불가 또는 검수 필요 항목>
   ```

8. 생성 또는 갱신한 Notion 페이지 링크와 처리한 페이지 범위, OCR 제한을 사용자에게 보고한다.

## PDF 입력 처리

1. 원본 PDF는 수정하지 않는다. 파일명, 전체 페이지 수, 요청한 페이지 범위를 먼저 확인한다.
2. 텍스트가 포함된 PDF는 `pdftotext` 또는 동등한 추출 도구로 빠르게 확인할 수 있지만, 그 결과만으로 표·그림·코드·배치를 확정하지 않는다.
3. 요청 범위의 PDF 페이지를 `pdftoppm -png -r 200 <입력.pdf> <임시-접두사>`로 PNG로 렌더링한다. 중간 PNG는 임시 경로에만 두고 Notion에 업로드하지 않는다.
4. 렌더링한 PNG를 열어 글자 선명도, 표 잘림, 그림과 코드 가독성을 확인한다. 문제가 있으면 DPI를 높여 다시 렌더링하거나 사용자에게 더 선명한 원본을 요청한다.
5. 각 PNG는 위의 Pi OCR 명령으로 처리하고, 페이지 번호를 OCR 결과와 Notion 출처에 유지한다. PDF에 이미지가 아닌 선택 가능한 텍스트가 있어도, 시각 요소가 있는 페이지는 이미지 OCR 결과와 대조한다.
6. 출력 Notion 노트의 출처에는 `PDF 파일: <파일명>`과 `페이지: <범위>`를 기록한다. 원본 PDF와 페이지 이미지 전체는 사용자가 명시적으로 요청하지 않는 한 Notion에 첨부하지 않는다.

## 검증 기준

- 실제 Pi 프로세스가 실행됐고 Qwen 결과가 반환됐는지 확인한다. 실패 시 Codex 결과로 Pi OCR을 대체했다고 주장하지 않는다.
- 교재 이미지와 OCR 결과의 제목, 숫자, 코드, 표를 표본 검수한다.
- PDF는 렌더링 PNG를 실제로 확인해 OCR 대상 페이지가 선명하고 누락되지 않았는지 검증한다.
- Notion 저장 전에는 대상 위치와 기존 노트 중복 여부를 확인한다.
- Notion에 비밀번호, 쿠키, 액세스 토큰, 교재 이미지 전체 또는 저작권 보호 원문 전체를 저장하지 않는다.

## 제한과 중단 조건

- 사이트 로그인이 필요하지만 인증된 브라우저가 없으면 교재 내용을 우회 수집하지 않는다.
- 브라우저 캡처, Pi OCR, Notion 연결 중 하나라도 사용할 수 없으면 가능한 단계까지만 수행하고 막힌 이유와 사용자가 할 일을 명확히 알린다.
- 한 번에 처리할 교재 범위가 크면 단원 또는 PDF 10페이지 이하로 나눠 사용자 확인 뒤 계속한다.
