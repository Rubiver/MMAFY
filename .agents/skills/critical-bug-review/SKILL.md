## 사용 시기

프로젝트의 특정 단계(phase) 완료 후, 생성된 소스코드와 로그를 검토하여 버그를 탐지하고 수정해야 할 때 사용합니다.

## 기능

- 소스코드 정적 분석을 통한 버그 탐지
- 로그 파일(`./docs/current-phase-log.md`) 분석을 통한 오류 식별
- [BLOCKING] 또는 [NIT] 형식으로 문제 보고
- BLOCKING 문제 수정 및 관련 테스트 재실행

## 보고 형식

### [BLOCKING]

심각한 오류. 이 문제가 있으면 해당 단계를 통과할 수 없습니다.

- 오류 위치 (파일명:라인번호)
- 오류 내용
- 수정 방안

### [NIT]

사소한 오류. 수정을 권장하지만 즉시 치명적이지는 않음.

- 오류 위치 (파일명:라인번호)
- 오류 내용
- 수정 방안

## 실행 절차

### 1. 로그 확인

- `./docs/current-phase-log.md` 파일을 읽어서 최근 단계의 실행 로그 확인
- 에러, 경고, 실패한 테스트 등 문제 징후 식별

### 2. 소스코드 분석

- 로그에 나타난 파일들의 소스코드 검토
- 정적 분석 도구(LSP diagnostics) 활용
- 논리적 오류, 타입 불일치, 누락된 처리 등 확인

### 3. 문제 보고

- [BLOCKING] 또는 [NIT] 형식으로 문제점 보고
- 각 문제마다 위치, 내용, 수정 방안 명시

### 4. 결과 판단

- **BLOCKING 없음** → 해당 단계 **PASS**
- **BLOCKING 있음** → 해당 단계 **FAIL**, 수정 필요

### 5. 수정 및 재실행 (BLOCKING 있는 경우만)

- BLOCKING 문제 최소화 범위 수정
- 관련 테스트 재실행하여 해결 확인
- 수정 후 다시 검토하여 BLOCKING이 사라졌는지 확인

## 규칙

1. 수정 범위는 요청된 문제에만 국한한다. 인접 코드 리팩토링 금지
2. NIT 문제는 수정하지 않고 보고만 한다 (사용자 결정에 따름)
3. 테스트 재실행은 수정한 코드와 직접 관련 있는 테스트만 실행
4. 모든 보고는 한국어로 작성 (기술 용어는 영문 유지 가능)
5. 중국어 한자 절대 사용 금지
