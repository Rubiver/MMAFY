## 사용 시기

사용자가 특정 phase 의 구현 완료를 검증해달라고 요청할 때 이 스킬을 사용한다.

예:

- "phase-1 완료 검증해줘"
- "phase-2 테스트해봐"
- "이 phase 다 된 거 맞아?"

## 기능

1. **핵심 기능 검증**: 현재 phase 에서 구현해야 할 핵심 기능이 실제로 동작하는지 확인
2. **체크리스트 검증**: phase 문서(phase-*.md) 에 정의된 완료 기준을 하나씩 확인
3. **자체 수정**: fail 발견 시 원인을 파악하고 코드를 수정한 후 재검증
4. **테스트 재실행**: 수정 후 관련 테스트케이스를 반드시 재실행하여 통과 확인
5. **엄격한 판단**: "거의 다 된 것", "대체로 완료"는 pass 안 감. 완전히 구현되어야 pass

## 완료 기준

각 phase 문서(phase-*.md) 에는 완료 기준 체크리스트가 정의되어 있다.

- 체크리스트의 **모든 항목이 O**이면 → **PASS**
- 체크리스트의 **항목 중 하나라도 X**이면 → **FAIL**
- 체크리스트에 X 가 있으면, 수정 후 재검증
- 재검증에서도 X 가 남으면 → 최종 FAIL

## 검증 방법

### 1. phase 문서 읽기

`phases/phase-N.md` 파일을 읽어서 완료 기준 체크리스트를 확인한다.

### 2. 구현 파일 확인

체크리스트의 각 항목에 대해 실제 구현 파일이 존재하는지, 코드가 제대로 작성되었는지 확인한다.

- 파일이 없는 경우: X
- 파일이 있지만 핵심 로직이 구현되지 않은 경우 (예: TODO, 미구현 함수, 빈 함수): X
- 파일이 있고 핵심 로직이 완전히 구현된 경우: O

### 3. 테스트 실행

체크리스트와 관련 테스트케이스가 있다면 반드시 실행한다.

- 테스트가 실패하면: X (해당 항목 수정 후 재실행)
- 테스트가 통과하면: O

### 4. 실제 동작 확인

단 파일 존재만 확인하는 것이 아니다.

- 함수가 실제로 원하는 로직을 구현했는지 코드 읽기
- API 엔드포인트가 실제로 작동하는지 테스트 실행
- **웹 클라이언트인 경우**: Playwright MCP 를 활용하여 UI 컴포넌트가 실제로 렌더링되는지, 사용자가 기대하는 동작이 제대로 이루어지는지 브라우저에서 직접 검증한다.
- **웹 클라이언트가 아닌 경우**: 관련 테스트 또는 수동 검증 방법으로 동작 확인

## 실행 절차

1. 검증할 phase 번호 확인 (예: phase-1, phase-2)
2. 프로젝트 성격 파악 (웹 클라이언트 / 서버 / 기타)
3. `phases/phase-N.md` 읽기
4. 완료 기준 체크리스트 추출
5. 각 항목에 대해:
   a. 구현 파일 확인
   b. 코드 레벨에서 로직 검증
   c. 테스트 실행 (있는 경우)
   d. **웹 클라이언트인 경우**: Playwright MCP 로 브라우저 검증 (UI 렌더링, 사용자 동작, 상호작용 등)
   e. O 또는 X 판정
6. 전체 결과 집계:
   - 모두 O → **PASS**
   - 하나라도 X → **FAIL** (원인 보고, 수정 시도, 재검증)
7. 최종 결과 보고

## 판정 기준

| 판정 | 조건 |
|------|------|
| PASS | 체크리스트 전체 O |
| FAIL | 체크리스트에 X 하나라도 존재 |

## 수정 규칙

fail 항목 발견 시:

1. **원인 파악**: 왜 실패했는지 코드/테스트 분석
2. **수정**: 실제 원인을 해결하는 코드 수정
3. **재검증**: 수정 후 같은 체크리스트 항목 다시 확인
4. **재테스트**: 관련 테스트 재실행

수정이 불가능하거나 근본적인 문제가 있으면 그 사실을 명시하고 보고한다.

## 금지 사항

- "거의 완료", "대부분 구현됨"은 pass 로 인정하지 않음
- 파일 존재만 확인하고 로직은 확인하지 않음
- 테스트 없이 구현만 보고 pass 하지 않음
- 체크리스트 항목을 건너뛰지 않음

## 보고 형식

검증 결과를 다음 형식으로 보고한다:

```
## Phase N 검증 결과

### 체크리스트

| 항목 | 결과 | 비고 |
|------|------|------|
| 항목 1 | O | 구현 완료 |
| 항목 2 | X | TODO 남아있음 |
| 항목 3 | O | 테스트 통과 |

### 최종 결과: FAIL / PASS

### 수정 내역 (있는 경우)
- 항목 2 수정: TODO → 실제 구현
- 관련 테스트 재실행: 통과

### 비고 (있는 경우)
- 추가 설명
```
