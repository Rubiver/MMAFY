## 사용 시기

사용자가 특정 스킬의 SKILL.md 파일을 검토해달라고 요청할 때 이 스킬을 사용하세요.

## 검증 항목

검사 대상 스킬의 다음 사항을 점검합니다:

### 1. YAML frontmatter

- 상단에 YAML frontmatter가 존재하는지 확인 (`---`로 감싸진 영역)
- `name` 필드가 있는지 확인 (필수)
- `description` 필드가 있는지 확인 (필수)
- YAML 형식이 올바른지 확인

### 2. 파일 구조

- YAML frontmatter 하단에 Markdown 본문이 위치하는지 확인
- YAML과 Markdown 경계가 명확히 구분되는지 확인 (`---`로 닫힘)

### 3. 스킬 이름 규칙

- `name` 필드의 값이 kebab-case인지 확인 (예: `skill-validator`, `code-reviewer`)
- kebab-case 기준: 소문자 영문자와 하이픈(-)만 사용, 하이픈으로 시작/끝나지 않음, 연속 하이픈 없음
- 디렉토리 이름이 `name` 필드와 일치하는지 확인

### 4. 언어 준수

- 파일 전체에 중국어 한자가 포함되어 있지 않은지 검사
- 한글로 쓰인 한자어는 허용 (예: 사용, 목적, 설명, 규칙, 검증)
- 영문 코드 및 기술 용어는 허용

### 5. Markdown 본문 구조

- `## 사용 시기` 또는 이에 상응하는 섹션이 존재하는지 확인 (언제 이 스킬을 사용하는지 명시)
- 스킬의 기능과 역할을 설명하는 섹션이 존재하는지 확인
- 구체적인 지침이나 실행 절차가 포함되어 있는지 확인
- 섹션 헤딩이 적절한 계층 구조를 이루는지 확인 (##, ### 등)

### 6. description 필드 품질

- 설명이 간결하고 명확한지 확인 (한 문장 정도로 요약 가능한 수준)
- 스킬의 핵심 역할과 목적이 포함되어 있는지 확인
- 불필요하게 길거나 모호한 표현이 없는지 확인

### 7. 내용 품질

- 설명이 명확하고 모호하지 않은지 확인
- 불필요한 반복이나 중복이 없는지 확인
- 가독성을 해치는 과도한 형식이 없는지 확인

## 검증 실행 절차

1. 먼저, 해당 skill 을 생성하기 전에 사용한 프롬프트나 문서가 있는지 사용자에게 묻는다. 없다면 간단하게라도 적어줄 수 있냐고 부탁한다.
2. 검사 대상 파일 경로 확인 (없으면 사용자에게 요청)
3. 파일이 실제로 존재하는지 확인
4. 파일 읽기
5. 위 검증 항목 하나씩 점검
6. 발견된 문제점을 항목별로 정리
7. 수정 권장사항 포함하여 보고
