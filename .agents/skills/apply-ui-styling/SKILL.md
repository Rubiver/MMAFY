## 사용 시기

UI 스타일링 판단부터 적용, 검증까지 전체 과정을 담당합니다. 에이전트가 UI 관련 구현을 진행해야 하는 단계에 도달했을 때 활성화됩니다.

## 판단 절차

먼저 현재 프로젝트의 성격을 파악합니다:

1. **서버 프로그램인가?** (CLI, API 서버, 백엔드 서비스 등)
   - 디자인이 전혀 필요 없으면 이 단계를 건너뜁니다.

2. **웹 클라이언트인가?** (React, Vue, Next.js, Svelte 등)
   - 아래 적용 규칙을 따릅니다.

3. **기타 UI 방식인가?** (QT, Electron 등)
   - 사용 가능한 스타일링 프레임워크/도구를 검토한 후, 추천 방식과 그 이유를 사용자에게 설명하고 허가를 받습니다.

## 웹 클라이언트 적용 규칙

### 1. Tailwind CSS 기본

- Tailwind CSS 가 프로젝트에 구성되어 있지 않으면 먼저 세팅합니다.
- 세팅 범위: 패키지 설치(`npm install -D tailwindcss postcss autoprefixer`), 설정 파일 생성(`npx tailwindcss init -p`), 프레임워크별 설정(Next.js: `app/globals.css` 또는 `pages/_app.css`에 지시어 추가), `tailwind.config.js/ts` 의 content 경로 설정

### 2. 반응형 디자인

- 모바일과 PC 모두에서 레이아웃이 깨지지 않고 적절히 표시되어야 합니다.
- `sm:`, `md:`, `lg:`, `xl:` 등 Tailwind 반응형 접두사를 적극 활용합니다.
- 모바일 퍼스트 접근을 기본으로 합니다.

### 3. Playwright MCP 백그라운드 캡쳐

- UI 적용을 진행하면서 **반드시** Playwright MCP 로 백그라운드에서 화면을 캡쳐합니다.
- 캡쳐는 최종 검증이 아닌 **진행 과정의 피드백 수단**입니다:
  1. UI 변경 적용 → 2. 즉시 Playwright 캡쳐 → 3. 결과 확인 → 4. 문제 시 수정 → 재검증
- 주요 뷰포트 (모바일 375px, 태블릿 768px, 데스크톱 1280px+) 에서 렌더링 결과를 확인합니다.
- 캡쳐된 이미지를 기반으로 레이아웃 문제, 반응형 깨짐, 겹침, 잘림 등을 검증합니다.

### 4. UI 품질 기준

- UI 가 일반적인 기준에서 못생겼다면 개선해야 합니다.
- 구체적으로 다음 사항을 점검하고 개선합니다:
  - **여백**: 요소 간 여백이 부족하지 않은지 (너무 빽빽하거나 너무 텅 비지 않게)
  - **정렬**: 텍스트와 요소가 일관된 그리드/정렬을 따르는지
  - **색상**: 텍스트와 배경의 대비가 충분한지, 일관된 팔레트를 사용하는지
  - **타이포그래피**: 폰트 크기 계층이 명확한지 (제목/본문/보조 텍스트 구분)
  - **일관성**: 유사한 요소가 동일한 스타일을 사용하는지
- 개선이 필요하다고 판단되면 즉시 수정하고, Playwright 캡쳐로 재검증합니다.

## 실행 순서

1. 프로젝트 성격 판단 (서버 / 웹 / 기타)
2. 웹 클라이언트인 경우 Tailwind CSS 존재 여부 확인
3. Tailwind 미존재 시 세팅
4. UI 스타일링 적용 (반응형 고려)
5. Playwright MCP 로 백그라운드 캡쳐 및 검증
6. 문제 발견 시 수정 후 재검증

## 규칙

- 모든 설명과 주석은 한국어로 작성합니다.
- 중국어 한자를 절대 사용하지 않습니다.
- Tailwind CSS 가 없는 웹 프로젝트라면 먼저 세팅합니다.
- 반응형 디자인은 필수입니다.
- Playwright MCP 캡쳐는 생략할 수 없습니다.
