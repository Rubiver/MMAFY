# 콘텐츠 개발 백로그

이 문서는 PRD와 현재 구현을 대조해 만든 다음 콘텐츠 개발 순서다. 콘텐츠 개발을 요청받으면 에이전트는 가장 높은 우선순위의 `READY` 항목 하나를 선택해 구현·검증·기록한다. 설계에 큰 영향을 주는 수치나 규칙이 비어 있으면 구현 전에 사용자에게 확인한다.

## 자동 진행 규칙

1. 작업 시작 전 이 문서에서 가장 높은 우선순위의 `READY` 항목을 찾는다.
2. 해당 항목의 선행 조건과 완료 기준을 확인한다.
3. 공용 프로토콜, 서버 검증, 클라이언트 화면, 테스트를 함께 갱신한다.
4. 자동 테스트와 빌드를 실행하고, 웹 화면 변경이면 Playwright MCP로 375px·768px·1280px를 검증한다.
5. 완료하면 상태를 `DONE`으로 바꾸고 다음 항목을 `READY`로 바꾼다. 막히면 `BLOCKED`와 사유를 기록한다.

## 현재 구현 기반

- 완료: 방 코드와 최대 25명, 역할 배정, 이동·충돌, 처치·시체·신고, 회의 채팅·투표, 정전·발전기 복구·환풍구, 긴급 회의 종, 회로 연결·물품 운송·보안 카드·자료 정렬·냉각수 배합·협동 공통 임무, 제한 시간 긴급 과부하, 결과·다음 판 흐름, 기본 관전.
- 공통 원칙: 결과에 영향을 주는 거리·역할·생존·쿨타임·정답·승패는 서버만 확정한다.

## 사용자 테스트 피드백과 회귀 점검

- **수정·화면 검증 대기 — 처치·신고 회귀:** 처치 직후 마피아 우세를 확정해 시체 신고 기회를 없애던 서버 경로를 고쳤다. 이제 신고 회의 결과 처리 뒤 승패를 확정한다. 자동 회귀 테스트는 통과했고, 실제 다중 참가자 및 Playwright 화면 검증이 남아 있다.
- **수정 완료 확인 필요 — 바리케이드 끼임:** 바리케이드 설치 뒤 좌표 보정으로 참가자가 바리케이드와 겹쳐 이동하지 못한 문제가 있었다. 사각 충돌 범위와 서버 승인 좌표 복구를 구현했으나, 다음 플레이 테스트에서 설치 직후·이동 중·동시 참가자 상황을 다시 확인한다.
- **테스트 편의 — 이동 속도:** 개발·테스트 환경에서는 기본 이동 속도를 크게 높인다. 실제 게임 밸런스 값과 분리하고, 운영 빌드에는 적용되지 않도록 명시적으로 제어한다.
- **관전 개선:** 사망자는 한 명의 고정 시점이 아니라 살아 있는 참가자 사이에서 관전 대상을 전환할 수 있어야 한다. 이동·채팅·투표 권한은 계속 제한한다.
- **2026/08/24 유저 테스트:** 마우스·[F] 처치 입력, 사망자 관전, 물품 운송의 실제 운반 표시와 완료, 마피아 환풍구 양방향 이동이 작동하지 않는 문제가 보고됐다. 자동 회귀와 실제 다중 참가자 검증을 함께 수행한다.
- **2026/08/24 추가 유저 테스트:** 긴급 회의 종·신고·발전기·회로·물품 상호작용이 불안정하고 마지막 처치도 실패했다. 클라이언트 2.4미터 안내와 서버 2미터 검증 불일치, 지나치게 엄격한 조준 조건을 최우선 수정한다.
- **2026/08/24 추가 유저 테스트:** 신고 뒤 서버가 이동을 멈추지만 회의 UI가 나타나지 않아 진행이 막혔다. 회의 화면의 3D 캔버스 위 오버레이 여부를 검증한다.
- **수정·화면 검증 대기 — 검은 화면:** 관전 카메라에 추가한 양수 `useFrame` 우선순위가 자동 렌더를 비활성화해 검은 화면을 만들던 경로를 제거했다. 자동 테스트·생산 빌드는 통과했고 실제 화면 검증이 남아 있다.
