# 콘텐츠 개발 백로그

이 문서는 PRD와 현재 구현을 대조해 만든 다음 콘텐츠 개발 순서다. 콘텐츠 개발을 요청받으면 에이전트는 가장 높은 우선순위의 `READY` 항목 하나를 선택해 구현·검증·기록한다. 설계에 큰 영향을 주는 수치나 규칙이 비어 있으면 구현 전에 사용자에게 확인한다.

## 자동 진행 규칙

1. 작업 시작 전 이 문서에서 가장 높은 우선순위의 `READY` 항목을 찾는다.
2. 해당 항목의 선행 조건과 완료 기준을 확인한다.
3. 공용 프로토콜, 서버 검증, 클라이언트 화면, 테스트를 함께 갱신한다.
4. 자동 테스트와 빌드를 실행하고, 웹 화면 변경이면 Playwright MCP로 375px·768px·1280px를 검증한다.
5. 완료하면 상태를 `DONE`으로 바꾸고 다음 항목을 `READY`로 바꾼다. 막히면 `BLOCKED`와 사유를 기록한다.

## 현재 구현 기반

- 완료: 방 코드와 최대 25명, 역할 배정, 이동·충돌, 처치·시체·신고, 회의 채팅·투표, 정전·발전기 복구·환풍구, 긴급 회의 종, 회로 연결 공통 임무, 기본 관전.
- 공통 원칙: 결과에 영향을 주는 거리·역할·생존·쿨타임·정답·승패는 서버만 확정한다.

## 우선순위 백로그

### P0 — 시설 전략 묶음

| 상태 | 콘텐츠 | 선행 조건 | 완료 기준 |
| --- | --- | --- | --- |
| DONE | 문·셔터 개폐와 잠금 | 공용 장치 상태 확장 | 시민은 가까운 문을 열고 닫을 수 있으며, 마피아는 잠글 수 있다. 서버가 거리·권한·상태를 검증하고 모든 화면에 동기화한다. |
| DONE | CCTV 관제실 | 문 상태와 전력 상태 | 시민은 관제실에서만 CCTV를 열 수 있고 조작 중 이동할 수 없다. 정전 또는 통신 장애 때 CCTV가 꺼진다. |
| DONE | 통신 장애 | CCTV 관제실 | 마피아가 통신을 끊으면 CCTV와 회의 관련 정보가 제한되고, 시민이 지정 장치에서 복구할 수 있다. |
| READY | 경보·바리케이드 | 문·셔터 개폐 | 시민이 제한 횟수로 동선을 보호할 수 있고, 마피아에게 우회 또는 해제 수단이 있다. |
