# 프로젝트 작업 규정

이 문서는 모든 작업자가 반드시 따르는 핵심 규정이다. 다른 문서와 충돌할 경우 사용자 지시를 가장 먼저 따르고, 그 다음 이 문서를 따른다.

## 언어와 문서

- 모든 문서, 화면 문구, 코드 주석은 한국어를 우선으로 작성한다. 사용자는 한국인으로 가정한다.
- 프로젝트 전체에서 중국어 한자를 쓰지 않는다. 한자어도 한글로 적는다.
- 함수와 메서드에는 역할, 입력, 반환, 예외나 부작용을 설명하는 JSDoc 또는 동등한 문서를 작성한다.
- 불명확한 요구사항은 임의로 정하지 않는다. 작업을 멈추고 사용자에게 질문한다.

## 파일과 보안

- 실제 실행 코드는 오직 `codes/` 디렉터리에 작성한다. 루트에 코드 파일을 만들지 않는다.
- `codes/.gitignore`, `codes/.env`, `codes/.env.example`만 사용한다. 루트 `.gitignore`나 루트 환경 파일을 만들지 않는다.
- 비밀값, 접속 정보, 토큰, 비밀번호는 코드와 문서에 넣지 않고 환경변수로 처리한다.
- `codes/.env`는 절대 커밋하지 않는다. 필요한 키 이름과 안전한 예시는 `codes/.env.example`에만 둔다.

## 개발과 검증

- 멀티플레이 판정은 서버 권한 방식으로 구현한다. 클라이언트의 이동, 처치, 상호작용, 임무, 투표, 역할 요청은 모두 서버에서 검증한다.
- 위치는 매 화면 프레임이 아닌 초당 10~20회 갱신을 기본으로 하며, 화면에서는 보간 처리한다.
- 웹 검색이 필요하면 Playwright MCP를 우선 사용하고 Google 대신 Bing 또는 DuckDuckGo를 사용한다. 검색어는 짧고 구체적으로 작성한다.
- 웹 클라이언트 테스트는 Playwright MCP로 한다. 성공한 화면은 전체 화면으로 촬영해 `docs/screenshots/`에 저장한다.
- Playwright MCP를 사용할 수 없으면 웹 화면 검증 작업을 즉시 중단하고 그 사실을 보고한다.
- 실행 포트를 사용했다면 해당 페이즈가 끝날 때 프로세스를 종료해 포트를 정리한다.
- Python 작업은 먼저 `uv` 사용 가능 여부를 확인한다. 없으면 개발자에게 요청한다. `pip`와 `requirements.txt`는 쓰지 않는다. Python은 가상환경에서 `uv init --python 3.12`, `uv add`, `uv run` 방식으로만 다룬다.

## 단계 관리

- 각 페이즈 문서 마지막에는 테스트 완료 체크리스트를 둔다.
- 작업 성공 또는 실패가 발생할 때마다 `docs/current-phase-log.md`에 즉시 기록한다.
- 기록 시각은 반드시 `date` 명령으로 확인한 서울 시간이며, `년/월/일/시/분/초` 형식으로 쓴다.
- 매 페이즈 완료 시 체크리스트를 갱신하고 한국어 커밋 메시지로 커밋한다.
- 세션 종료 전 루트 `resume.md`에 완료 내용, 현재 상태, 다음 작업, 주의점을 갱신한다.

## 게임 고유 규정

- 방 정원은 최대 25명이며 6명 미만은 권장하지 않는다.
- 공정성에 영향을 주는 결과는 서버만 확정한다. 거리, 시야, 쿨타임, 생존 여부, 역할 권한을 검증하지 않은 결과 전파를 금지한다.
- 함정과 치명적 교란에는 대응할 시간 또는 수단을 제공한다. 예고 없는 즉사 구조를 피한다.
- MVP 범위를 벗어나는 역할, 경쟁, 음성, 결제 기능은 사용자 승인 없이 추가하지 않는다.
